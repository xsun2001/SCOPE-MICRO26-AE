# Overview

This table compares the current repo implementations, not idealized paper architectures.

Assumptions:

- `N`: systolic-array edge length / square tile size.
- `H`: PINNACLE `stripHeight`.
- `δ_full`: `1` when PINNACLE's two strip rows fill the whole array (`2H = N`), else `0`.
- `T = ceil(L / N)`.
- `E`: FuseMax `eLen`. If one `QK^T` dot product spans the whole head dimension in one slice, use `E = D`.
- The tile-cycle column counts from the first `Q`/`K` preload-launch point to the cycle where `PV` (or the closest implemented equivalent) is fully retired. It excludes scratchpad initialization, writeback, and final normalization unless the cell says otherwise.

Notes:

- For `PINNACLE`, the exact repo-validated done latency is `16N + 3H + 8 + δ_full + (2 - c)(N + 1)`. The compute-only number above is derived by removing scratchpad init `2(H + 4N + 2)` and the writeback/done tail `N + 3`.
- For `PINNACLE` with `c = 2`, the streamed `alpha -> PV` handoff puts the array core in the `7N + O(1)` regime when `H` is treated as a fixed approximator depth. The only extra exact-cycle caveat is `δ_full`, the one-cycle full-strip bubble when `H * c = N`.
- For `SystolicAttention`, `6N + 10` is the requested preload-to-`PV` window; `8N + 30` is the end-to-end tile latency including final normalization.
- For `FuseMax`, the current wrapper computes one output-feature slice at a time, so its timing is not directly comparable to the full-tile engines above.
- For `FuseMax`, `Float` and `DWFloat` are structurally supported by the public type interface, but this repo currently validates only the `SInt` path. `Float` still inherits the current simplified 1-cycle division assumption, and `DWFloat` depends on external IP.
- When a design note says full FA is "not implemented", this overview does not invent a kernel-level cycle formula.
